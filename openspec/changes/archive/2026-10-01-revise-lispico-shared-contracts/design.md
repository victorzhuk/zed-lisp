# Design

## Approved contract

The authoritative wire and permission contract is [contracts.md](../../add-lispico-development-support/contracts.md). Project/catalog schema version 2 and snapshot schema version 1 have independent versions. Keep namespace-cell, library, profile, and source-version/source-revision rules; do not silently accept old schemas. Schema validation can enforce structural constraints but cannot prove manifest completeness, filesystem confinement, or installed-state freshness. Those properties belong to producers and consumers.

## Bounded execution sequence

1. Establish behavior-level schema acceptance/rejection cases in `tests/config.rs`: paired manifests, both-cell entries, source-only/catalog-only provenance shapes, expected digest syntax, exclusive packs root/snapshot selection, readable versus unreadable snapshot entries, and unsupported old versions. Reuse existing conformance coverage; do not re-pin wording or incidental defaults.
2. Implement the two version-2 schemas and new closed snapshot schema. Match the approved path/digest/payload shape; semantic byte ordering, secure reads, actual hashes, and invalidation remain upstream consumer work, not fictitious schema capabilities.
3. Migrate examples and resource validation as one coherent set. Preserve language associations and explicit library enablement; correct host source mappings from reviewed current source without inventing catalogs or installed snapshots. A source-directory packs example remains valid without installed-state claims.
4. Run bounded schema/package tests, build/lint, and a throwaway validator against shipped examples plus representative valid/invalid resources. Update existing README, examples README, and changelog only after behavior lands. Record actual outcomes; do not claim actual Zed or installed-pack parity here.

## Testing and verification

Mode: existing-service-strict. `make test`, `make check-package`, `make build`, and `make lint` are the existing local wrappers. Honor their time/worker limits and bound other commands. Permanent tests assert meaningful boundary acceptance/rejection, not source text or duplicate generated bytes. Runtime source mutation, confinement, and installed-store capture tests belong to their owners. Actual Zed acceptance remains a later dependency.
